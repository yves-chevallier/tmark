# 08 — Language server and editor integration

Crate: `tmark-lsp`. Editor client: `editors/vscode`. Spec: §Tooling roadmap
item 6.

## Shape

`lsp-server` + `lsp-types` (synchronous, single main loop, a worker thread
for parse/resolve). Not `tower-lsp`: no async runtime in a process whose
work is CPU-bound and whose state is one map of open documents.

```
stdio ──▶ main loop ──▶ DocumentStore { uri → (text, Document, Resolved, diagnostics) }
                            │
                            ├── on change: parse (sync, < 50 ms) → publish parse diagnostics
                            ├── debounce 150 ms: resolve + lint on worker → publish all diagnostics
                            └── requests read the latest snapshot
```

Workspace: `tmark.toml` at the root (profile, lint levels, `include`
bases); a project is the set of `.md`/`.tm` files below it. Files not open
are loaded through `FsLoader` when resolution needs them (includes,
inventories) and cached by mtime.

## The VS Code extension

Today: the TextMate grammar generated by `scripts/build_grammar.py` from the
spec's recognisers, injected into Markdown, plus a `tmark` language id. At
milestone 3 the generator moves to Rust (`cargo run -p tmark-ir --example
grammar`) so that role names, node words and prefixes come from the
registries, and the extension gains an LSP client that starts the bundled
`tmark-lsp` binary (per-platform download like `ruff`/`tinymist`, or a WASM
fallback). The grammar stays: semantic tokens are an overlay, not a
replacement, because they arrive after the first paint.

File detection: `.tm`, `.tmd`, `.tmark` are TMark; `.md` is TMark when the
front matter has a `press` key, when the workspace has a `tmark.toml`, or
when the user sets `files.associations`. Otherwise the extension only
contributes the injected grammar and stays quiet (no diagnostics on a README).

## Protocol details worth fixing early

- Positions: the LSP speaks UTF-16 column offsets; `LineIndex` converts from
  byte offsets once, both ways. Test with emoji and combining characters.
- Diagnostics are published per file, including for included files that are
  not open (the workspace folder is the boundary).
- Every request is answered from the last complete snapshot; a request never
  waits for a parse.
